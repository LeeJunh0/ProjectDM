# 실제 32×32 게임 리소스

사용 범위는 캐릭터·몬스터(중간보스·보스 미리보기 포함)·스킬·드랍템입니다. 배경 타일·UI 패널·글꼴·셰이더로 만드는 파동과 파티클은 이 비트맵 스프라이트 변환 대상에 포함하지 않습니다.

실제 게임용 출력은 `Assets/GameContent/Art/Pixel32/` 아래 **개별 프레임마다 32×32px PNG**입니다. 각 픽셀은 하나의 RGBA 색상값을 가지며 알파는 0 또는 255입니다. Point 필터·무압축·밉맵 없음으로 불러옵니다. 큰 PNG에 도트처럼 그린 이전 방식과 달리 실제 파일과 Sprite rect가 모두 32×32입니다.

| 폴더 | 내용 |
| --- | --- |
| `Characters/` | 후드 마법사 4종, 각 4방향×4프레임 및 정면 기본 자세 |
| `Monsters/Meadow/`, `Monsters/Dungeon/` | 각 5종×4프레임, 보스 도달 미리보기 각 2프레임 |
| `Skills/` | 연쇄 번개, 스플래쉬, 운석, 얼음 조각 |
| `CollectiblesAndProjectiles/` | 경험치 5종·재화 5종·마나·상자·기본 투사체와 관련 프레임 |
| `Fallback/` | 과거 플레이어/몬스터 컨트롤러의 대체 경로에 필요한 32픽셀 프레임 |

고해상도 제작 원본은 보존합니다. 눈·얼굴·갓 형태 수정에는 내장 `image_gen`을 사용하고, Unity 에디터에서 원본 스프라이트를 프레임별 32픽셀 격자로 정규화합니다. 애니메이션 그룹별 공통 월드 좌표 캔버스를 사용하여 원래의 기준점과 상대 동작을 보존하고, PPU를 조절하여 화면에서 보이던 크기를 유지합니다. 원본 PNG·GUID·슬라이스는 변경하지 않습니다.

몬스터 눈은 검은색 바탕과 작은 흰 반사광으로 변경합니다. 축소할 때 사라질 수 있는 검은 눈 안의 작은 흰 반사광은 네이티브 한 픽셀로 보존합니다. 새싹 정령의 얼굴은 같은 방향을 유지하며, 버섯은 갓 오른쪽 윤곽과 무늬를 프레임 사이에서 유지하도록 수정합니다. 32픽셀 출력 단계에서 새싹 얼굴 영역과 버섯 머리 영역을 첫 프레임의 공통 픽셀로 고정하여 한 픽셀의 형태 변화도 방지합니다. 팔다리·머리 바깥 잎의 동작은 유지하고, 네 프레임이 서로 다른 걷기 포즈인지 검증합니다. 두 몬스터는 이동에 따른 자동 좌우 반전도 끕니다. 다른 몬스터의 이동 방향 반전은 유지합니다.

`Assets/Resources/ProjectDM/Pixel32Catalog.asset`는 게임용 스프라이트와 원본 식별 문자열을 연결합니다. 원본 텍스처에 대한 직접 참조를 보관하지 않습니다. 스테이지·캐릭터 기본 자세·모든 애니메이션 키·스킬 설정·드랍 프리팹은 출력 스프라이트로 연결합니다. 런타임에서 옛 아틀라스를 임의 절단하던 투사체·보석·재화·몬스터 대체 경로도 32픽셀 카탈로그를 먼저 사용합니다.

연쇄 번개와 운석의 기준 위치, 얼음 조각·스플래쉬의 실제 지름은 새 캔버스에 맞게 보정합니다. 프레임 수·재생 속도·전투 수치·판정·저장 데이터는 유지합니다. 원본 그림을 수정한 후 `Project DM/Export All Gameplay Artwork To Native 32px`를 실행하면 기존 슬라이스와 같은 경로·ID로 다시 내보내고 참조를 연결합니다.

2026-10-26 에디터 정리로 일회성 검증·임포트·초기 설치 스크립트와 자동 임포트를 삭제했습니다. 이미 제작된 에셋·슬라이스·메타는 유지하며, 32픽셀 내보내기와 애니메이션 미리보기는 남아 있습니다. 아래 검증 수치는 제작 당시 기록입니다.

최종 출력은 210개 PNG 프레임입니다. 네이티브 32픽셀·모든 연결·머리 영역 고정·4개 동작 유지·흰 반사광 보존·반복 내보내기 ID/스킬 위치 보존 1,560개 검증을 통과했습니다. 스테이지 194개, 캐릭터 아트 230개, 과거 아트 240개, 스프라이트 참조 188개, 마나 17개, 드랍 파티클 169개, 스킬 시각화 153개, 중간보스 28개, 고유 마법 3,548개, 보상·등급 371개 검증도 통과했습니다. 실제 Main/Addressables에서 두 스테이지를 반복 전환하고, 새싹·버섯이 플레이어 양쪽에 있어도 반전되지 않는지 검증했습니다. 실행 파일 빌드나 수동 장시간 플레이는 포함하지 않습니다.

쥐의 2~4번째 프레임에서 귀가 검은 눈처럼 바뀌던 원본 오류를 복원했습니다. 내장 이미지 편집 결과 중 귀의 세 영역만 원본에 반영하여 다른 픽셀을 보존하고, 게임용 32×32 프레임을 다시 내보냅니다. 네 프레임 모두 분홍 귀·귀 내부 반사광 없음·실제 검은 눈과 흰 반사광 유지를 검사합니다.

전용 확인 창은 Unity의 **Project DM → 리소스 애니메이션 미리보기**에서 엽니다. 재생·프레임 이동·속도·픽셀 격자·캐릭터 4방향 비교를 지원합니다. 캐릭터 위쪽 프레임의 크기도 정면 기준으로 보정했습니다. [사용법과 검증](Resource-animation-preview.md)을 참고하세요.
