# 레트로 몬스터 리소스 적용

현재 실사용 리소스는 [실제 32×32 게임 리소스](Native32-art.md)를 사용합니다. 일반 몬스터는 4프레임·검은 눈과 작은 흰 반사광을 사용하고, 새싹 얼굴과 버섯 갓은 동작 중 형태와 방향을 유지합니다. [4프레임 · 거친 도트 수정](Monster-animation-4frame.md)은 고해상도 제작 원본 단계의 기록입니다. 매끈해진 6프레임 시트는 폐기했습니다. 아래는 최초 2프레임 적용 당시의 기록입니다.

앞서 선택한 [몬스터 시안](Monster-Retro-Reference-v1.png)의 왼쪽 `RETRO 32` 표현을 기준으로, 현재 캐릭터와 함께 쓸 초원·던전 몬스터를 내장 `image_gen`으로 제작했습니다. 굵은 도트 덩어리, 계단 모양 윤곽, 재질색에 가까운 연한 외곽선과 약한 하이라이트를 사용합니다. `RETRO 32`는 시안의 스타일 이름이며 실제 PNG가 32×32라는 뜻은 아닙니다.

| 리소스 | 저장 위치 | 구성 |
| --- | --- | --- |
| 초원 | `Assets/GameContent/Art/Monsters/ProjectDM_Meadow_Retro_2Frame_v1.png` | 풀 슬라임, 새싹 정령, 들판 고블린, 버섯 요정, 멧돼지, 고목 수호자 |
| 던전 | `Assets/GameContent/Art/Monsters/ProjectDM_DungeonDenizens_Retro_2Frame_v1.png` | 동굴 박쥐, 지하 쥐, 사슬 유령, 돌거미, 망령 갑옷, 봉인 수문장 |

두 PNG는 각각 1024×1536, 2열×6행, 12프레임입니다. 일반 몬스터 10종과 보스 미리보기 2종, 총 24개 프레임을 임포트합니다. [생성·수정 프롬프트](Retro-monster-prompts.json)를 기록했습니다. 투명 부분에 남은 RGB 값은 발광이 아니며 실제 알파가 0인 부분은 렌더되지 않습니다. 픽셀 데이터를 스크립트로 다시 그리거나 리샘플링하지 않습니다.

던전은 "도트가 거칠지 않고 너무 반듯하다"는 피드백에 따라 같은 종류·디자인을 유지하고 내장 이미지 편집으로 다시 그렸습니다. 잔 픽셀과 촘촘한 명암을 줄이고, 큰 계단 모양의 윤곽·넓은 색 덩어리·단순한 재질 면으로 바꿨습니다. 사슬·칼·거미 다리·보스 문양에도 같은 굵은 도트를 적용했습니다. 갑옷과 수문장 사이에는 투명 간격을 확보했습니다. 같은 PNG 경로와 스프라이트 ID를 유지하여 재임포트합니다. 임포트 전에 보스의 월드 높이를 보관하여, 새 슬라이스의 픽셀 높이가 달라져도 기존 미리보기 크기를 유지하도록 했습니다. 거친 도트 수정본도 아트·스테이지·중간보스·고유 마법 검증을 통과했고 실제 SpriteRenderer 렌더를 확인했습니다.

사용자가 거절한 슬라임·방패 스켈레톤·고블린·버섯·멧돼지·골석 수호자의 새 던전 세트는 PNG와 `.meta`, 생성 원본·톤 수정본에서 삭제했습니다. 해당 세트를 다시 생성하거나 적용하지 않습니다. 1스테이지는 승인한 초원, 2스테이지는 별개의 던전 전용 생물 구성입니다. 사슬·룬·갑옷은 외형 표현이며 새 특수 공격/패턴을 추가한 것은 아닙니다.

`Project DM/Import Retro Monster Artwork` 메뉴가 실제 알파 경계로 행과 열 사이의 투명한 구분을 찾고, 두 프레임을 같은 크기의 사각형으로 나눕니다. 생성 시트의 좌우 배치 오차는 각 그림의 수평 중심에 맞춰 슬라이스 위치와 피벗을 조정합니다. 큰 보스의 주먹도 고정 중앙선으로 잘리지 않도록 합니다. 슬라이스가 옆 열을 침범하지 않도록 제한하고, 그림의 중심을 피벗에 맞춥니다. 공통 세로 범위를 사용해 프레임 전환 때 불필요한 좌우 이동이 생기지 않도록 합니다. Point 필터, 96 PPU, 무압축, 밉맵 없음, 런타임 CPU 읽기 없음으로 설정합니다.

`Stage1_Meadow.asset`, `Stage2_Dungeon.asset`의 일반 몬스터·보스 참조를 새 시트로 교체했습니다. 일반 몬스터는 기존 2프레임 수동 재생 경로로 통일합니다. 풀에서 재사용하는 적의 Animator는 비활성화되므로 같은 SpriteRenderer에 두 재생기가 쓰지 않습니다. 중간보스는 현재 몬스터를 키우는 기존 방식대로 새 외형을 사용합니다. 최종 보스는 기존 도달 미리보기에 새 그림이 표시되며, 기존 미리보기의 월드 높이를 유지합니다.

초원 몬스터 이름과 던전의 기존 5개 성장 슬롯은 유지하고, 던전 표시 이름을 새 종류에 맞게 바꿉니다. 체력·이동·스폰·보상·중간보스 배율과 확정 상자·처치 파동은 기존 설정을 사용합니다. 성장 화면의 스테이지 아이콘과 결과 화면도 같은 스테이지 참조를 사용합니다. 과거 PNG·슬라이스·GUID, 바닥 타일과 저장 데이터는 보존합니다. `StageArtPipeline.ImportContent`도 마지막에 설치된 레트로 시트를 적용하므로 기존 스테이지 재구성 메뉴로 외형이 되돌아가지 않습니다. 이미 구성된 과거 몬스터 시트는 다시 슬라이싱하지 않습니다.

검증 진입점은 `ProjectDM.Editor.ProjectDMMonsterArtSetup.RunBatch`입니다. 투명도·프레임 쌍·수평 중심·반복 임포트 ID·보스 크기, 스테이지 선택 경계, 과거 아트 메타데이터, 중간보스와 고유 마법 회귀를 검사합니다. `PrototypePlaySmoke.RunBatch`는 실제 Main/Addressables에서 두 스테이지의 전 몬스터 출현, 두 프레임 반복 재생, 중간보스의 새 리소스 상속을 확인합니다. 실제 SpriteRenderer·Tilemap 조합은 `Logs/RetroMonsters-Stage1.png`, `Logs/RetroMonsters-Stage2.png`에 저장합니다. 각 렌더는 위쪽에 보스 미리보기·플레이어·확대된 중간보스 외형, 아래 두 줄에 일반 몬스터의 첫째·둘째 프레임을 보여줍니다.

2026-10-22 최종 적용 검증: 새 몬스터 아트 70개, 스테이지 194개, 과거 아트 메타데이터 240개, 스프라이트 참조 187개, 중간보스 28개, 고유 마법 3,548개 검증이 통과했습니다. 스테이지 재구성 후 새 외형·이름 유지와 과거 스프라이트 ID 보존 195개 검증, 실제 Main 플레이 스모크도 통과했습니다. 두 배경의 최종 렌더를 직접 확인했습니다. 수동 조작 플레이나 실행 파일 빌드 검증은 포함하지 않습니다.
