# 성장과 수치 설계 기준

2026-11-03 사용자 결정.

## 플레이 분량

- 캐릭터 타입마다 주요 성장을 완성하는 목표는 약 3시간.
- 공통 성장은 캐릭터 간 공유한다. 다른 타입도 전용 성장을 충분히 진행할 수 있도록 전용 숙련 구간을 둔다.
- 스킬 세 개는 초중반에 해금한다. 후반 분량을 스킬 해금 대기로 채우지 않는다.
- 기존 성장 ID와 구매 단계, 저장 잔여 단계는 보존한다. 새로운 비용 곡선은 옛 저장의 단계 변환과 분리한다.

## 숫자 범위

2026-11-03 추가 결정: 최종 피해가 작게 끝나는 것이 아니라, 실제 180초 런에서 조건을 갖춘 강력한 스킬 치명타가 90만~99만대에 도달해야 한다. 영구 성장 완료 + 런 위력 10단계 + 해당 스킬 위력 3단계의 기준 치명타를 약 975,000으로 조정한다. 런 강화 99단계를 요구하지 않는다.

세 위력 숙련의 합계 72단계에 따라 피해·몬스터 체력 배율을 3차 곡선으로 늘린다. 최초 배율은 1이며 런 시작에 고정한다. 실제 피해는 100,000까지 선형, 이후 완만한 증가를 적용하고 999,999를 넘지 않는다. 표시만 자르는 것이 아니라 체력에서 빼는 피해에 적용한다. 큰 피해 구간에서는 치명타 등 추가 배율의 최종 효율도 완만해진다.

- 최종 성장에서도 전투 피해, 몬스터 체력, 마나, 개별 성장 구매 가격, 한 런의 재화·경험치 보상을 1,000,000 미만으로 설계한다. M 단위 진입을 목표로 삼지 않는다.
- 표시값만 잘라서 제한하는 방식은 사용하지 않는다. 실제 테이블과 조합 가능한 효과의 범위를 검사한다.
- 무한히 반복한 누적 처치·누적 플레이 시간·평생 수입은 전투 밸런스 상한과 구분한다. 보유 재화도 무한 반복으로 쌓을 수 있으므로 저장값을 임의로 잘라서 버리지 않는다.
- 영구 성장과 런 중 강화는 주로 합산한다. 무제한 지수 배율과 후속 타격의 재귀 증폭은 피한다.

## 성장 체감

- 첫 런에는 적은 수의 몬스터를 상대한다. 생성 목표·최대 개체 수·한 번의 생성량·젠 속도를 성장시켜 더 많은 적을 상대하게 된다.
- 생성량과 젠 수가 서로 막혀 효과가 사라지지 않도록 관련 성장에 초반부터 접근할 수 있어야 한다.
- 재화 및 경험치 획득량, 드랍 등급, 마나 회수, 자석·끌어오기 범위도 성장 대상으로 둔다.
- 피해 숫자 외에 관통·연쇄·범위·공전·지속 공격으로 성장 장면을 만든다. 강해져도 이전 몬스터를 섞어 상대적인 강함을 볼 수 있게 한다.
- 핵심 감정은 이전에 도망치던 무리를 다음 런에서 쓸어버리는 설욕, 적을 모아 한꺼번에 터뜨리는 순간, 쌓인 보상을 거두는 수확이다.
- 보이는 적·드랍·이펙트를 줄여 성장 장면을 약하게 만들지 않는다. 성능 개선은 풀링·일괄 렌더링·탐색 비용을 대상으로 한다.

## 검증

- 실제 Unity 전투 시스템으로 초기화 → 전투 → 아이템 획득 → 런 강화 선택 → 결과 → 합법적인 영구 성장 구매를 반복한다.
- 자동 이동·구매 전략, 랜덤 시드, 고정 시간 간격과 결과/선택/구매에 가산한 예상 시간을 기록한다.
- 자동 플레이를 사람의 플레이 시간이나 조작감 평가로 표현하지 않는다. 첫 타입과 공통 성장을 물려받은 후속 타입을 구분한다.
- 기존 Python 전투 근사 모델은 전용 스킬과 현재 작성된 성장지도 전체를 재현하지 않으므로 타입 완성 시간의 근거로 사용하지 않는다.
- 보스 전투는 현재 도달 미리보기 상태다. 보스 공략 시간까지 포함한 완제품 플레이 분량은 별도 검증해야 한다.
