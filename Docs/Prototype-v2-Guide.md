# 인게임 프로토타입 V2

## 바로 확인

`Assets/Scenes/Main.unity`를 실행합니다. GameManager의 **테이블 시작 시간 사용**은 기본 켜짐이며, 씬에 있던 5초 디버그 값 대신 테이블의 40초 + 영구 시간 성장으로 시작합니다. 수동 시간을 쓰려면 이 옵션을 끕니다.

- 이동: 기존 WASD/방향키. 자동 기본 공격.
- 레벨업: 실제로 획득 가능한 효과를 최대 3개, 중복 없이 제시. 클릭 또는 1/2/3.
- 새 저장의 첫 레벨업은 공격력/공격속도 2개만 표시됩니다. 번개 해금 구매 후 **다음 런**에는 번개 획득 카드도 표시됩니다.
- TAB: 중심 8방향 → 5개 고리로 퍼지는 전체 화면 성장 지도. 첫 진입은 전체 크기에 맞춰 표시합니다. 좌측 상단 **전체 보기**로 다시 맞추고, 휠 확대/축소·가운데 버튼 드래그로 탐색합니다. 우측 상단 보유 재화, 마우스 오버 설명 → 노드 클릭 → 좌측 하단 구매. 작은 전체 보기에서는 이름/숫자 대신 아이콘과 구매 칸을 우선 표시하고 자세한 값은 툴팁/구매 패널로 확인합니다.
- 중앙 시작 노드는 **기본 공격 해금**이며 처음부터 해금 완료(1/1) 상태입니다. 별도 구매나 공격 제한 없이 기존 기본 자동 공격을 사용합니다. 중앙 칸의 툴팁과 상세 패널은 기본 공격을 설명합니다. 노드 칸에만 마우스 오버·선택 이벤트가 있고, 칸 밖 이름/타이틀·설명 텍스트는 표시 전용입니다.
- 이미 투자한 노드와 구매 조건이 열린 노드, 그리고 이들에 직접 연결된 다음 노드까지만 정보를 공개합니다. 재화 부족은 공개 범위에 영향을 주지 않습니다. 다음 노드가 잠겼다면 조건을 미리 확인할 수 있지만 그 칸 때문에 더 먼 노드까지 공개되지는 않습니다. 미공개 칸은 어두운 빈 칸/희미한 연결선으로 남기고 아이콘·이름·구매 횟수·툴팁·상세 선택은 숨깁니다. 기존 구매와 이관된 소수 단계는 계속 보입니다.
- 기존처럼 런 도중 성장 지도를 볼 수 있지만, 구매한 효과는 다음 런부터 적용됩니다. 지도 우측 하단의 **새 런 시작**으로 바로 확인하거나 **플레이로 복귀**로 현재 런을 계속할 수 있습니다. 새 런을 시작하면 미수집 보상은 사라지고 이미 모은 재화는 유지됩니다.
- 시간 종료 또는 플레이어 체력 소진: 기존 통계/돌아가기/다시 시작. 코인은 수집 시 저장되므로 종료 시 중복 지급하지 않습니다. 바닥에 미수집된 보상은 지급하지 않습니다. 피격으로 종료된 경우 남은 시간이 0으로 잘못 표시되지 않도록 종료 순간의 값을 유지합니다.

## 스테이지·보스 목표 라인 (임시)

중앙 **기본 공격 해금**에서 12시 방향으로 `스테이지 1 → 1스테이지 보스 → 스테이지 2 → 2스테이지 보스 → 스테이지 3 → 최종보스 (임시)`의 한 줄 목표 경로를 표시합니다. 3스테이지는 임시 구성이지 최종 콘텐츠 수 확정이 아닙니다. 첫 스테이지는 시작 표시, 후속 목표는 준비 중 상태이며, 전체 목표 라인은 미리 볼 수 있습니다. 일반 성장의 한 링크 공개 규칙은 유지됩니다.

목표 칸은 청색 계열 테두리, 마지막 임시 보스는 금색 테두리입니다. 칸에 마우스 오버하면 설명을 보여주고, 클릭하면 좌측 상세 패널이 **목표 정보**로 바뀝니다. 이름/설명 텍스트 자체에는 마우스 이벤트가 없습니다. 작은 전체 보기에서는 표식을 우선 표시하므로 확대해서 이름·설명을 확인하세요.

현재 범위는 목표 노드·연결·설명·표시입니다. **보스 노드 구매, 실제 스테이지 이동, 보스 전투, 처치 후 경로 해금은 아직 미구현**이며 임시 칸을 클릭해도 재화를 쓰거나 완료를 기록하지 않습니다. 기본 스테이지 이후 이동 조건도 아직 확정하지 않았습니다. 기존 180초 최종보스 도달 미리보기와 런 타이머는 변경하지 않았습니다.

보스 설명의 리미트는 남은 런 시간이 0이 되는 순간이 아니라 **해당 스테이지 런의 실제 경과 시간**입니다. 노드를 해금하고 시간 보충으로 런을 리미트까지 유지했을 때 등장하는 설계이며, 일반 몬스터 해금 단계/재화 등급과는 독립입니다. 지금은 각 보스의 임시 설명 리미트를 180초로 뒀으며 실제 전투 연결 시 스테이지별 런 설정과 함께 적용해야 합니다.

테이블은 `PrototypeGrowth.json`의 `goalLine` 배열입니다. 일반 `rows/nodes`와 분리했으므로 20개 성장 행 / 80개 구매 칸 / 222회 구매는 그대로입니다. 필드:

- `id/name/description`: 목표 ID·이름·설명.
- `kind`: `stage` 또는 `boss`, 스테이지/보스 쌍의 순서.
- `stage`: 실제 스테이지 번호(1부터), 일반 몬스터 단계 아님.
- `parent`: 첫 목표는 `ROOT`, 이후는 바로 전 목표 ID.
- `x/y`: x=0, y는 음수로 증가해 12시 방향. 연결 간격은 120~380.
- `limitSeconds`: 보스 목표의 경과 시간 리미트 설명 값(현재 180). 스테이지 칸은 0.
- `icon`: 기존 `gem/slime` 스프라이트. 새 이미지는 생성하지 않았습니다.
- `final`: 마지막 보스 목표의 강조 표시.

중앙 목표 통로를 확보하기 위해 **표시 좌표만** 일반 성장 노드를 좌우로 벌립니다. 중심축에 걸친 가지는 가까운 부모/자식의 방향으로 배치해 다른 칸을 관통하지 않게 합니다. 기존 테이블의 성장 좌표·ID·구매 조건·가격·효과·저장은 변경하지 않았습니다. 목표 배열이 없는 커스텀 테이블은 기존 좌표 그대로 표시합니다. 표시용 전체 그래프는 목표 6개와 루트를 포함해 87칸이며, 전체 보기 계산에 목표 라인까지 포함됩니다.

검증: `Tests/ObjectiveLineRegression.ps1` 23,411개(목표 순서·리미트·카드/연결선 겹침·레거시 테이블), Unity 성장 QA 245,490개/2,671회 실제 구매/레이아웃 발견 0개, 기존 Unity 회귀 104개와 Main 플레이 스모크 통과. 헤드리스 좌표/상태 검증이며 실제 화면 가독성·마우스 클릭의 실측은 별도입니다. Main 스모크 시작에는 격리 프로젝트의 Unity 검색 인덱서 내부 예외가 기록되지만, 이후 게임 초기화와 플레이 검증은 통과했습니다.

빠른 확인 시에는 플레이 **전에** GameManager 인스펙터의 **실험 모드 (저장하지 않음)**을 켜는 것을 권장합니다. 기존 진행을 읽지만 재화 지급/처치/구매/도달 결과가 실제 저장에 반영되지 않습니다. 플레이 중 이 옵션을 바꿔도 현재 세션의 저장 정책은 바뀌지 않습니다.

런 우측 상단의 **디버그 도구 열기**에는 재화 +1,000, 이번 런 공격 효과 3종 획득, 공격 효과 발동 100%, 스폰 단계 변경, 최종보스 도달 미리보기, 플레이어 피격 테스트(-10), 치명타 100%가 있습니다. 별도 **디버그 레벨업** 버튼도 유지합니다. 일반 모드에서는 지급 재화와 처치 스택이 실제 저장됩니다. 임시 스킬/100%/스폰 단계는 런 재시작 시 초기화됩니다. 보스 미리보기는 실제 보스 도달 업적을 기록하지 않습니다.

## 테이블

모두 `Assets/Resources/ProjectDM/Data` 아래 JSON TextAsset입니다. 인스펙터에서 다른 TextAsset으로 교체할 수도 있습니다. 테이블 변경은 플레이를 종료하고 다시 실행하면 반영됩니다. Play 도중 부분 교체/핫 리로드는 하지 않습니다.

| 파일 | 편집 대상 |
| --- | --- |
| PrototypeBalance.json | 기본 공격, 치명타, 플레이어 체력/피격 무적/접촉 범위, 이동, 시작 시간, 보스 리미트, 처치 시간 보충, 경험치 곡선, 몬스터 HP/속도/접촉 피해/보상/영구 처치 해금, 단계별 스폰 수/간격/가중치 |
| PrototypeSkills.json | 런 카드 이름/설명/아이콘/동·은·금 등급, 획득 조건, 최대 런 단계, 확률/피해율/범위/지연 |
| PrototypeGrowth.json | `rows`: 20개 영구 성장의 가격 곡선/효과/최대 단계/몬스터 단계 조건/선행 조건. `nodes`: 80개 방사형 노드의 위치/연결/1~3회 구매 범위 |

몬스터/단계 배열 순서는 슬라임 → 스켈레톤 → 고블린 → 버섯 → 멧돼지입니다. `minStage`는 0부터 시작합니다. `nextUnlockKills`는 **해당 몬스터**의 누적 영구 처치 수입니다. 소모하지 않으며, 선행 몬스터 순서대로 해금됩니다. 기존 몬스터는 다음 단계에서도 섞여 나옵니다. 스폰 단계는 처치 시 바로 변경되지만 기존 개체를 교체하지 않고 다음 리필부터 새 구성을 사용합니다.

`initial/target/cap/batch/refillSeconds/weights`는 초기 수/유지 목표/절대 최대 수/1회 리필 수/기본 간격/종류별 가중치입니다. 개체 수 성장은 목표·최대 수에 더하고 초기 수는 비례 증가합니다. 리스폰 성장은 간격을 빈도 배율로 나눕니다. 몬스터 HP/속도는 경과 시간으로 자동 상승하지 않습니다. 테이블 스폰 거리 사용이 켜져 있으면 기획의 초기 3~5, 리필 5~8 거리를 적용하고 타일맵 내부로 제한합니다.

전체 성장 구매는 222회이며 이를 80개 노드에 나누었습니다. 기존 65개 노드/177회 구매는 유지하고, 은화·금화·에메랄드·자수정의 개별 확률과 경험치 등급 상승 확률을 각각 3개 노드×3회 구매(합계 15개 노드/45회)로 추가했습니다. 노드당 최대 3회, 스킬 해금·다중 공격 등은 1회, 마지막 잔여 구간은 1~2회입니다. 일반 능력치의 1회 효과/최대 성장량은 앞선 압축안을 유지합니다: 공격력 +20%p(첫 구매 보너스 +46%p를 합쳐 처음에는 +66%), 공격속도 +4%p, 시작 시간 +2초, 시간 보충 확률 +0.2%p, 재화 +4%p, 경험치 +6%p, 필드 개체 수 +5마리, 리스폰 빈도 +5.04%p. 공격속도/리스폰의 %는 **빈도 증가**이며 간격의 직접 감소가 아닙니다.

재화는 몬스터별 `currencyChances` 확률표(동화/은화/금화/에메랄드/자수정 순서)에서 **하나만** 추첨합니다. 해금되지 않은 재화는 제외하고 나머지 확률을 100%로 정규화합니다. 성장의 `silverDropChance/goldDropChance/emeraldDropChance/amethystDropChance`는 각각 낮은 재화 확률을 해당 재화로 전환하며, 해금 범위 안에서는 여러 등급을 건너뛸 수 있습니다. 경험치는 `experienceGrade`와 `experienceGradeChance`의 기존 한 단계 상승을 유지합니다. `lootGrades` 지급량 1/2/3/5/9와 실제 프리팹은 그대로 연결됩니다. 구매 효과는 다음 런부터, 몬스터/재화 해금은 해당 런에서도 바로 적용됩니다. 옛 `currencyGradeChance` 구매는 은화 확률로 한 번 이관합니다. 설정과 검증은 [드롭 등급 안내](LootGrades.md)를 참고하세요. `lootGrades`가 있는 테이블에서는 해당 등급 지급량이 기준이며 몬스터의 옛 `coins/xp`는 등급 없는 커스텀 테이블 호환용입니다.

영구 공통 발동 확률 `proc`를 `chainChance/splashChance/meteorChance`로 분리했습니다. 각 스킬은 1회 +약 0.6667%p, 3회 노드 3개(총 9회), 최대 +6%p입니다. 해당 스킬의 영구 해금이 선행 조건이고 몬스터 단계 조건도 유지합니다. 기본 확률은 각각 12%/12%/4%이며 한 스킬의 확률 구매가 다른 스킬에 영향을 주지 않습니다. 런에서 선택하는 임시 공통 확률 카드(+2%p)는 기존대로 유지합니다. 이번 분리는 영구 성장 그래프에 적용합니다.

기존 가격 곡선은 `ceil(baseCost × costGrowth^rank × (1 + (latePriceScale - 1) × (1 - exp(-rank / 8))))`입니다. `legacyMaxRank`가 있으면 새 1회가 대응하는 옛 단계들의 비용을 합산합니다(리스폰처럼 배수가 정수가 아니면 경계 단계 비용을 비례 배분). 이후에는 `1 - exp(-새 rank / costRampRanks)`로 초반 상승을 완화합니다. `costRampRanks`는 현재 2이며 0이면 완화하지 않습니다. 일반 성장은 앞선 가격과 동일합니다. 개별 스킬 확률의 첫 가격은 각 10이며, 세 종류의 총 최대 구매 비용을 합치면 기존 공통 확률 전체 비용의 약 100.45%입니다. 노드가 바뀌어도 누적 가격은 초기화하지 않습니다.

`rows.requires`는 성장 종류별 선행 해금 제한입니다. `nodes.parent`는 연결선의 기준이며 `parentRanks`가 양수이면 **그 선행 노드에서 필요한 실제 구매 횟수**도 지정합니다. 0이면 시각 연결만 유지합니다. 중심 8개 시작 노드에서 바깥쪽으로 퍼지고, 각 고리는 능력치·시간·보상·개체 수·스킬 성장을 섞어 배치합니다. 두 번째 고리는 선행 1회로 열리는 경로가 있고, 이후에는 앞쪽 다른 성장 노드 완료를 요구합니다. 같은 능력치 후속 노드는 자신의 이전 구간도 완료해야 하므로 한 능력치만 계속 구매할 수 없습니다.

기본 지도는 가까운 안쪽 고리의 다른 성장 노드에 연결합니다. 연쇄 번개·스플래쉬·운석의 첫 확률 노드는 해당 스킬 해금 바로 옆에 두고 직접 연결합니다. 반대편까지 가로지르는 선을 방지하기 위해 기본 테이블의 연결 길이는 380 좌표 단위 이하이고, 연결선이 다른 노드 칸을 관통하지 않는지 회귀 테스트에서 검사합니다. 노드 ID·구매 범위·가격·효과는 위치/연결 수정으로 바뀌지 않습니다.

`x/y`는 화면 중심 기준 좌표이고 기존 5개 고리 반경은 230/420/610/800/990, 노드 수는 8/12/16/16/13개입니다. 재화별 확률·경험치 등급 노드 15개는 가까운 기존 성장 노드 옆에 분산 배치했으며 기존 65개 위치/연결은 바꾸지 않았습니다. `growthId`는 성장 행 ID, `startRank`는 누적 구매 시작 위치(0부터), `ranks`는 해당 노드에서 구매할 횟수(1~3)입니다. 공격력 40회는 14개 노드, 공격속도 30회는 10개 노드에 분산했습니다. 테이블 검증은 범위 누락/중복·3회 초과·구매 조건 순환을 검사합니다. `nodes`가 없는 행 테이블도 자동으로 최대 3회씩 분할해 방사형으로 배치하지만, 원하는 경로/선행 조건은 명시적 `nodes`로 작성하는 것을 권장합니다. 현재 테이블은 20개 영구 성장/6개 런 선택 효과입니다(기존 15종 및 이전 통합 재화 확률 커스텀 성장 테이블도 로드 가능). 구매한 칸은 노드 하단에 금색으로 채워지고 완료 노드는 밝아집니다.

`chance/step/rankChanceStep`의 확률 수치는 0~1입니다. 0.12 = 12%, 0.0008 = 0.08%p. `damageRatio` 0.65 = 기본 공격력의 65%. 카드의 동·은·금 등급은 시각 구분이며 선택 확률 가중치를 숨겨서 추가하지 않습니다. 드롭 등급은 카드 등급과 별개이며 실제 지급량/외형에 연결됩니다. 효과 카드 설명의 실제 숫자는 테이블 수치로 생성합니다. `description`은 디자이너 메모/설명입니다. 아이콘은 기존 `bolt/gem/coin/slime` 스프라이트를 사용합니다. 신규 아트를 생성하지 않았습니다.

## 공격/시간 규칙

- 실제 적중에 일반 피해는 흰색, 플레이어 피격은 붉은색 `−숫자`, 치명타는 크게 표시되는 금색 `숫자!`가 떠오릅니다. 기본 공격·다중 공격·연쇄 번개·범위 효과 각각 실제 피해량을 표시하고 소수 피해도 보존합니다. 표시 수 제한은 피해 계산을 제한하지 않습니다. 숫자 연출은 별도 전투 난수를 소비하지 않으며 레벨업/성장 지도 중에는 멈춥니다.
- 치명타는 임시 기본 확률 5%, 피해 배율 2배입니다. `criticalChance/criticalMultiplier`로 조절합니다. 기본 공격과 다중 공격의 각 실제 적중에 독립 판정하며 공격 효과 확률을 변경하거나 효과 피해를 추가로 2배 하지 않습니다.
- 플레이어는 임시 체력 100, 접촉 거리 0.55, 피격 후 무적 0.6초입니다. `playerHealth/playerContactRadius/playerInvulnerability`로 조절합니다. 여러 적이 동시에 닿으면 가장 큰 접촉 피해를 1회 적용하고, 같은 프레임에 전부 중첩하지 않습니다. 몬스터의 `contactDamage`는 순서대로 1/2/4/3/6입니다. 체력은 좌측 하단에 표시하며 재시작 시 회복됩니다.
- GameManager의 **전투 데미지 숫자** 항목에서 표시 시간/크기/떠오르는 거리/분산/세 종류 색상/치명타 크기를 한글로 조절할 수 있습니다. 치명타·접촉 피해를 각각 끄는 옵션도 제공합니다. 체력·확률·피해량은 임시 테이블 값입니다.
- 숫자는 기본 0.55배로 시작 → 0.1초 동안 1.3배로 커짐 → 0.04초 유지 → 0.3초 동안 0.55배로 작아짐 순서입니다. **시작/최대/마지막 크기 배율**, **커지는/최대 크기 유지/작아지는 시간**, **크기 연출 속도 배율**로 조절합니다. 속도 2는 각 구간을 절반 시간에 재생하고 전체 표시 시간·이동 속도에는 영향을 주지 않습니다. 구간 합계가 표시 시간보다 길면 비례 축소해 작아지는 연출이 잘리지 않게 합니다. 일반 피해·피격·치명타에 공통 적용하고 치명타는 별도 크기 배율을 추가로 곱합니다.
- 연쇄 번개: 각 기본 적중에 12%, 원래 적을 제외한 근접 적 최대 2명, 공격력 65%, 연결 거리 3.
- 스플래쉬: 각 기본 적중에 12%, 반경 1.65, 공격력 80%. 원래 적이 살아 있으면 포함.
- 운석: 각 기본 적중에 4%, 0.65초 후 반경 2에 공격력 350%. 기본 볼트 낙하/바닥 표시/섬광으로 임시 연출.
- 다중 공격의 추가탄은 직접 피해 70%이며 모든 실제 적중에 독립 판정. 효과 피해는 추가탄에서도 기본 주탄 공격력을 기준으로 계산합니다.
- 같은 적중에서 여러 효과가 함께 발동할 수 있습니다. 기본 공격이 적을 죽여도 그 적중의 효과 판정은 유지합니다.
- 효과 피해는 다른 공격 효과를 재발동하지 않습니다. 별도 임의 내부 쿨다운을 넣지 않았습니다.
- 시간 보충은 모든 처치에 별도로 판정: 처음부터 8%, +1초. 영구 확률 성장 적용. 보충 시 +1s 임시 숫자가 떠오릅니다.
- 제한 시간 슬라이더는 남은 시간 ÷ 이번 런 시작 시간입니다. 보충 시 차오르며 100%를 넘기지 않습니다.
- 보스는 **한 런의 실제 누적 경과 시간**이 `bossElapsedSeconds`에 도달할 때 등장합니다. 현재 리미트 180초는 임시값입니다. 레벨업/성장 지도에서 멈춘 시간은 포함하지 않습니다. 시간 보충은 종료 시점만 늘리고 경과 시간을 변경하지 않습니다.
- 현재 보스는 기존 멧돼지 스프라이트 확대 미리보기 + 도달 화면입니다. 보스 HP/공격/승리 전투는 의도적으로 미구현입니다.

경험치는 소수값을 누적합니다. 코인은 보상 생성 시 소수 부분을 확률 반올림하여 낮은 획득량 성장도 기대값에 반영됩니다. 기본 코인은 확정 드롭, 추가 코인은 몬스터별 별도 확률, 상자는 별도 1.8%입니다. 경험치 문턱은 `ceil(7 × 1.5^(level - 1))`; 한 번에 여러 레벨을 올리면 선택 횟수를 큐에 보존합니다.

## 저장/검증/한계

기능별 클래스와 수동 의존성 주입 구조는 [게임 시스템 구조](GameArchitecture.md)를 참고하세요. GameManager에는 기존 한글 인스펙터 설정과 초기화·실행 연결만 남기고 전투·저장·런·UI의 상태는 각 시스템에서 관리합니다.

기존 재화 키 `PROJECT_DM_META_GOLD`는 유지합니다. 영구 랭크/처치/누적 런 통계는 `PROJECT_DM_PROTOTYPE_V2`에 저장하며 현재 형식은 버전 3입니다. 버전 1은 `legacyMaxRank / maxRank`로 일반 랭크를 환산하고 버전 2의 일반 랭크는 그대로 유지합니다. 작은 잔여 성장도 `partialRank`로 보존합니다. 예: 옛 공격력 4회 → 새 0회 + 0.8단계, 실제 효과는 +62%로 같고 노드에 `0.8/3`으로 표시됩니다.

기존 공통 `proc`는 버전 1에서 1회 +0.08%p, 버전 2에서 1회 +0.4%p였으므로 그 총 효과를 세 개 개별 스킬 확률에 **각각** 이관합니다. 공통 보너스는 원래 세 스킬 모두에 적용됐으므로 나눠서 1/3로 줄이지 않습니다. 새 형식은 다시 이관하지 않고 옛 `proc` 항목도 복구용으로 남겨둡니다. 원본 버전 1은 `PROJECT_DM_PROTOTYPE_V2_BEFORE_COMPRESSION`, 방사형/확률 분리 전 원본은 `PROJECT_DM_PROTOTYPE_V2_BEFORE_RADIAL`에 각각 1회 백업합니다. 재화·처치·런 수는 초기화하지 않고 실험 모드에서는 백업도 쓰지 않습니다. 더 오래된 공격/속도/행운 키도 삭제하지 않습니다. 형식이 맞지 않는 저장/테이블이면 초기화 오류로 표시하고 기존 저장을 덮어쓰지 않습니다.
