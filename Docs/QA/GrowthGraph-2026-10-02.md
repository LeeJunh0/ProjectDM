## 발견 사항

### GROWTH-01 — 작은 화면의 고정 정보창이 기본 노드를 가림 (P2)

- 재현 조건: 신규 진행, 실제 게임 출력 크기 724×400, 성장 화면의 기본 전체 보기.
- 현재 그래프는 화면 중앙을 기준으로 맞추지만 고정 정보창·보유 재화·탐색 버튼 영역을 피하지 않는다.
- 계산상 중심이 고정 UI 영역에 들어가는 공개 노드는 `ROOT`, `xp_1`, `population_1`, `extension_1`, `chain_1`, `respawn_1`, `xp_2`, `speed_3`, `time_2`의 9개다. 기본 공격 루트는 정보창 뒤에 놓인다.
- 해당 영역은 `IsPrototypeGraphOverlay`가 그래프 입력을 차단하므로 가려진 지점에서는 노드를 선택하거나 설명을 확인할 수 없다.
- 신규 진행의 1920×1080, 1280×720, 960×540 기본 전체 보기에서는 공개 노드 중심의 가림이 없었다. 확대·이동 후의 모든 배치를 보장하는 결과는 아니다.
- 원인: `FitPrototypeGraph`는 화면 전체 경계만 고려하고, `IsPrototypeGraphOverlay`는 별도의 고정 사각형을 사용한다.
- 권장 방향: 작은 화면에서는 정보창을 접거나 배치를 바꾸고, 전체 보기의 사용 가능 영역에 고정 UI 영역을 반영한다.
- 임시 대응: 게임 출력은 960×540 이상으로 확인하거나, 빈 영역에서 가운데 버튼으로 그래프를 이동한다.
- 관련 코드: `Assets/Scripts/Systems/UI/Growth/GrowthGraphView.cs`의 `FitPrototypeGraph`, `IsPrototypeGraphOverlay`, `DrawPrototypeGrowthDetails`.

### GROWTH-02 — 툴팁이 고정 패널 뒤에 그려짐 (P2)

- 재현 조건: 1920×1080에서 기본 공격 노드를 화면 좌표 `(40, 850)` 부근으로 옮기고 그 칸에 마우스를 올린다.
- 마우스 지점은 정보창 밖이라 정상 호버 대상이다. 툴팁은 `(60, 868, 330, 158)`, 정보창은 `(22, 858, 355, 198)` 영역에 놓인다.
- 툴팁은 `DrawMetaTreeCanvas` 내부에서 먼저 그려지고, 이후 `DrawPrototypeGrowthDetails`가 불투명한 패널을 덮는다. 계산상 위 재현 조건에서 툴팁 영역의 약 96%가 패널에 가려진다.
- 권장 방향: 툴팁은 그래프·고정 패널·탐색 버튼을 모두 그린 다음 마지막에 그린다.
- 임시 대응: 노드를 정보창에서 떨어진 위치로 옮겨 설명을 확인한다.
- 관련 코드: 같은 파일의 `DrawMetaTree` 54~55행, `DrawMetaTreeCanvas`의 마지막 호버 설명 호출, `DrawPrototypeGraphTooltip`.

두 사항은 **실제 구현의 사각형과 그리기 순서로 확인한 결과**이며, 정상 렌더링된 화면을 눈으로 확인한 결과는 아니다. 게임 코드 수정은 하지 않았다.

## 검증 한계

- 헤드리스 에디터에서는 `Event.current`가 OnGUI 외부에서 노출되지 않는다. 무효 이벤트를 성공한 입력 테스트로 처리하지 않고 입력 테스트를 건너뛴 것으로 기록했다.
- 실제 그래프 뷰·기본 스프라이트·UI 리소스를 사용한 격리 실행본도 준비했지만, 숨긴 실행 환경에서 정상 GUI 캡처와 주입 클릭을 확보하지 못했다. 검은 캡처 및 실패한 주입 클릭은 게임 결함의 증거로 사용하지 않는다.
- 실제 마우스 클릭·휠·드래그·툴팁 픽셀 확인과 시각적 가독성은 별도 수동 QA가 필요하다. 이 보고서는 완전한 시각 QA 완료를 의미하지 않는다.
- 4~5시간의 보스 최초 도달 목표는 이번 QA에서 실측하지 않았다. 구매 교착 검증과 장시간 플레이 밸런스 검증은 별개다.
