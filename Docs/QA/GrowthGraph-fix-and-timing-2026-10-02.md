# 성장 그래프 수정 및 플레이타임 검증 — 2026-10-02

## 결론

성장 그래프의 작은 창 노드 가림과 툴팁 그리기 순서를 수정했다. 기능/구매/저장/레이아웃 회귀는 통과했다. 정상 GUI 화면의 시각 QA와 실제 마우스 조작은 아직 수동 확인이 필요하다.

현재 테이블의 신규 진행 시뮬레이션에서는 **균형 성장의 보스 최초 도달 중앙값 4.14시간**, 필드 성장 4.34시간으로 4~5시간 목표에 가깝다. 공격 위주는 3.98시간으로 조금 빠르다. 빠른 선택이나 낮은 적중/수집 효율까지 고려하면 목표를 모든 플레이어에게 보장하지 못한다. 게임 밸런스 테이블은 변경하지 않았다.

## UI 수정 및 회귀

- `GrowthGraphView.FitPrototypeGraph`: 기존 중앙 전체 보기에서 공개 카드가 고정 UI와 겹치지 않으면 기존 배율/위치를 유지한다. 겹치면 정보창 위/오른쪽의 빈 영역 중 여유가 큰 영역에 그래프를 맞춘다. 작은 화면 전체 보기에는 0.04까지 축소가 필요하므로 휠 축소 한계도 맞췄다.
- Game 창 크기가 바뀌면 새 크기로 다시 맞춘다. 사용자가 확대/드래그한 뒤 고정 패널 뒤로 보낸 노드까지 항상 움직이게 하지는 않는다. `전체 보기`로 복원한다.
- 고정 패널의 표시/입력/QA가 같은 사각형 계산을 사용한다. 노드별 포인터 검사에 배열을 생성하지 않는다.
- 툴팁은 정보창·재화·탐색 버튼 다음에 마지막으로 그린다. 플레이로 이동한 프레임에는 남은 툴팁을 그리지 않는다.
- `GrowthGraphQa`는 수정 전 724×400의 루트 가림을 재현한다. 수정 후 1920×1080 / 1280×720 / 960×540 / 724×400, 신규/전부 성장, 진행 중/런 종료 상태에서 **카드 전체 사각형**이 고정 패널과 겹치지 않음을 검증한다. 툴팁/정보창 약 96% 겹침 시나리오도 유지하면서 그리기 순서를 검사한다.

검증 결과:

- 성장 QA: **145,790 단언 PASS / 2,131 구매 / 발견 사항 0**.
- 기존 Unity 전투·성장 회귀: **94 단언 PASS**.
- PowerShell 기존 회귀: 시스템 주입 3,808 / 성장 10,862 / 피해 숫자 878 단언 및 코인 슬라이스·통계 숫자 연출 PASS.
- 계산 모델 Python 회귀: **44 테스트 PASS**, 기존 V1/V2 모델 테스트 포함.
- 계산 모델과 실제 C# 구매 규칙 대조: **8,860 단언 PASS**, 모든 177개 가격, 세 전략 예시의 순차 구매·선행 조건·몬스터 단계·재화·런 스냅샷 검증.
- Main Play Mode 스모크: 실제 Addressables/플레이어/프리팹, 테이블 타이머·스폰 수, 레벨업·일시정지·스킬·보스 도달·재시작·실험 저장 모드 PASS.

원본 Main 씬과 실제 PlayerPrefs는 수정하지 않았다. Unity 검증은 `Temp/ClassRefactorTestProject`에서 수행했고 저장은 메모리 저장소/실험 모드를 사용했다. 열린 원본 에디터의 미저장 씬도 저장하지 않았다.

## 현재 테이블 기반 플레이타임

게임 업데이트 이후 옛 모델은 구매 압축·교차 선행 조건·개별 확률 등을 반영하지 않았다. 따라서 `simulate_current.py`를 추가해 실제 `PrototypeBalance/Growth/Skills.json`을 읽도록 했다. 가격은 C# float 필드를 일치시키고 실제 `PrototypeRules`와 다시 대조했다.

모델에 반영한 항목:

- 65개 노드, 총 177회 구매, 1~3회 노드 제한, 이전 단계 완료, 교차 부모 랭크·스킬·몬스터 단계 조건.
- 첫 구매 가격 유지, 옛 가격 묶음, `costRampRanks=2`, 누적 랭크 가격.
- 몬스터별 체력/속도/보상, 종별 누적 처치 해금, 혼합 스폰, 개체 수/최대 수/초기 수/리스폰 성장.
- 초기 40초 + 영구 시간 성장, 처치마다 기본 8% + 확률 성장으로 1초 보충, 한 런 실제 경과 180초에 보스 도달.
- 기본/추가탄별 발동, 세 스킬의 개별 영구 확률, 공통 런 확률, 효과 비재귀, 치명타는 직접 피해에만 적용.
- 공격속도의 영구×런 배율, XP/레벨업/선택지의 해금·최대 랭크·보장된 미획득 스킬 제안.
- 매 런 후 살 수 있는 합법 성장 중 가중 한계 이득/가격 순으로 재화를 사용. 최적 경로 탐색은 아니다.

신규 저장, 시드 0~19, 전략당 20회(총 60개 독립 진행). 아래는 **첫 보스 등장까지의 누적 시간**이며 보스 전투/승리를 포함하지 않는다. 메뉴 포함 시간은 현실 시간 근사, 전투 시간은 게임 내 시간이 흐른 시간의 합이다.

| 구매 전략 | 메뉴 포함 중앙값 | P10~P90 | 전투 시간 중앙값 | 중앙값 런 수 |
| --- | --- | --- | --- | --- |
| 균형 | 4.14시간 | 4.00~4.25시간 | 2.84시간 | 156 |
| 공격 우선 | 3.98시간 | 3.77~4.13시간 | 2.73시간 | 151 |
| 필드/경제 우선 | 4.34시간 | 4.21~4.42시간 | 2.98시간 | 163.5 |

세 전략의 60개 진행은 모두 8시간 계산 한도 내 보스에 도달했다. P10~P90는 이 표본의 분위수이지 신뢰구간/전체 플레이어 보장은 아니다. 옛 40표본 결과는 균형 4.56 / 공격 4.41 / 필드 4.91시간 중앙값이었다. 새 모델의 선택 전략·배율·치명타도 달라졌으므로 차이를 노드 변경 하나의 효과로 해석하면 안 된다.

4~5시간 사이에 들어온 표본 비율은 균형 18/20(90%), 공격 8/20(40%), 필드 20/20(100%)다. 공격 경로의 빠른 도달을 평균값만 보고 목표 충족으로 처리하지 않았다.

## 가정과 민감도

기본 적중률 90%, 재화/XP 묶음 수집률 85%. 수집 지연은 0.45초 + 거리×0.16초, 상자는 추가 상호작용 0.8초로 근사한다. 플레이어가 이동/회피해 살아남고, 적은 거리 0.6~3.0에 분산된다는 기존 방사형 전투 가정이다. 실제 플레이어 이동 경로·벽/필드 모서리·투사체의 다른 몬스터 요격·프레임 단위 판정은 재현하지 않는다.

메뉴 가정은 레벨업 선택당 2.5초, 종료 후 결과 4초 + 재시작 2초 + 성장 확인 5초, 구매당 2초다. 구매가 없는 런도 성장 확인 5초를 포함한다. 따라서 빠른 플레이의 목표가 순수 전투 시간 4~5시간이라면 현재 중앙값 2.7~3.0시간은 짧다. 카드 선택 속도에 따른 재계산은 결과 JSON의 `choice_seconds_sensitivity_same_campaigns`에 저장한다. 전투/구매 경로를 그대로 두고 선택에 머무는 시간만 바꾼 비교다.

| 레벨업 카드 선택당 시간 | 균형 중앙값 | 공격 중앙값 | 필드 중앙값 |
| --- | --- | --- | --- |
| 0.5초 | 3.51시간 | 3.38시간 | 3.69시간 |
| 1초 | 3.67시간 | 3.53시간 | 3.85시간 |
| 2.5초 (기본) | 4.14시간 | 3.98시간 | 4.34시간 |
| 5초 | 4.92시간 | 4.72시간 | 5.16시간 |

카드 1초 선택만으로도 세 전략 모두 목표 하한 4시간보다 짧다. 성장/결과 화면까지 더 빠르게 지나가면 추가로 짧아질 수 있다. 사용자가 원한 빠른 재투자·재진입 흐름을 기준으로 안정적인 4~5시간을 만들려면 재조정과 실제 이동 플레이 검증이 필요하다.

추가 독립 표본:

| 시나리오 | 표본 | 균형 전략 도달 중앙값 | P10~P90 |
| --- | --- | --- | --- |
| 수집률 65% (적중 90%) | 10 | 5.73시간 | 5.57~5.84시간 |
| 적중률 70% (수집 85%) | 10 | 5.92시간 | 5.72~6.23시간 |
| 플레이어 정지/접촉 허용 | 3 | 8시간 내 도달 0/3 | 도달 시간 없음 |

정지 시나리오는 적이 중심까지 접근하며 HP 100, 0.6초 무적, 반경 0.55, 겹친 몬스터 중 최대 피해만 적용한다. 일반 이동 플레이의 사망률 추정이 아니라 극단 스트레스다. 실제 피격 빈도가 높으면 기본 시간 예측이 맞지 않는다.

권장 다음 단계: 실제 플레이에서 누적 전투/메뉴 시간, 적중률, 수집률, 사망률을 측정하고 목표의 기준을 메뉴 포함/빠른 재진입 플레이로 확정한 뒤 가격/시간 보충을 조정한다. 보스 난이도는 이후 별도로 설계한다. 이번 요청에서는 UI 버그만 고쳤으며 수치 보정은 하지 않았다.

```powershell
python Tools/Balance/simulate_current.py --samples 20 --output Temp/Balance-current.json
python Tools/Balance/simulate_current.py --samples 10 --policy balanced --profile low_collection --output Temp/Balance-low-collection.json
python Tools/Balance/simulate_current.py --samples 10 --policy balanced --profile low_accuracy --output Temp/Balance-low-accuracy.json
python Tools/Balance/simulate_current.py --samples 3 --policy balanced --profile stationary --output Temp/Balance-stationary.json
python -m unittest discover -s Tools/Balance -p 'test_*.py'

```

근거: `Temp/Balance-*.json`, `Temp/GrowthGraphQa-fixed-final.log`, 격리 프로젝트의 `Logs/GrowthGraphQa-result.json`, `Temp/GrowthGraph-fixed-Regression.log`, `Temp/GrowthGraph-fixed-PlaySmoke.log`.
