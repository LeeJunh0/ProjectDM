# 성장 캠페인 QA — 2026-11-03

## 추가 수치 확장 검증

사용자의 추가 요청에 따라 실제 최종 스킬 피해를 90만~99만대로 확장했다. 기존의 낮은 피해만을 전제로 한 아래 최초 측정은 이 변경 전의 기록이다. 최초 피해·몬스터 체력은 유지하고, 세 영구 위력 숙련으로 실제 피해·체력 단위가 함께 커진다. 상한은 UI 포맷이 아니라 실제 체력 차감 경로에 적용한다. 자세한 식은 [프로토타입 가이드](../Prototype-v2-Guide.md)의 최종 피해 확장을 따른다.

새 캠페인의 `maxHit`는 실제 `EnemySystem`에 적용된 최대 단일 피해다. 기존 `damage`·`maxDamage` 필드는 단위 배율·치명타·보조 스킬 배율 적용 전의 기본 계산 입력이다. 숫자가 커졌다는 이유로 재화·경험치·가격을 함께 부풀리지 않으며 약 3시간 성장 흐름을 다시 검사한다.

| 타입 | 관측 최대 단일 피해 | 성장 완료 추정 | 런 수 |
|---|---:|---:|---:|
| 기본 발사 | 972,233 | 3.35시간 | 92 |
| 화염 | 999,966 | 2.85시간 | 40 |
| 번개 | 976,921 | 2.91시간 | 41 |

총 214런에서 999,999 초과 피해가 없었고 네 타입 모두 실제 90만대 이상의 피해를 관측했다. 빙결은 공전 성장으로 넓어진 얼음 고리를 파쇄가 덮도록 보정하고, 폭풍 첫 파동 강타를 추가한 뒤 재측정했다. 일반 몬스터 처치 흐름과 약 3시간의 성장 흐름을 유지한다. 시간은 위와 동일한 선택·구매 시간 가정이 들어간 자동 플레이 추정이다.

최신 성장지도 검사 3,831개를 통과했다. 실제 `EnemySystem` 피해 함수로 약 975,000을 적용하고 대상 체력이 그만큼 감소하는 검사를 포함한다. 빙결 폭풍의 첫 파동만 강하게 적용되고 두 번째부터 원래 지속 피해가 나오는 상태 검사도 통과했다. 수치·체력·가격·보상 및 999,999 실제 피해 상한 검사 813개를 통과했다.

## 목표와 범위

- 기본 마법사로 공통 성장부터 시작하고 이후 다른 타입으로 넘어가는 경로에서 타입당 약 3시간을 목표로 한다.
- 공통 성장은 공유한다. 후속 타입 테스트는 공통 성장·몬스터 종 해금 완료, 해당 타입 전용 성장 0, 보유 재화 0에서 시작한다.
- 전투·성장 구매 가격·한 런 보상을 100만 미만으로 설계한다. 제한은 표시가 아니라 실제 테이블 조합을 대상으로 검사한다.
- 보이는 몬스터·드랍·이펙트의 수를 줄이지 않았다.

## 방법

`Tests/CampaignPlaytest.cs`는 실제 Unity의 EnemySystem, CombatSystem, SkillSystem, PlayerCombatSystem, PickupSystem, LevelUpController, RunController 및 성장 구매 규칙을 호출한다. 전투와 이동을 30Hz로 계산하며 여러 계산 단계를 한 프레임에 수행한다. 적을 피하면서 가까운 아이템을 향해 이동하고, 실제로 제시된 카드에서 선택하며, 실제 모은 재화로 조건을 만족하는 노드만 구매한다. 스킬이나 보상을 임의로 지급하지 않는다.

사람의 플레이 실측이 아니다. 이동·회피·강화 선택은 단순한 봇 전략이다. 특히 초반에는 회피 때문에 아이템 회수를 놓칠 수 있다. 손으로 조작할 때의 재미, 체감 난이도, 최적 구매 순서의 시간은 별도 검증이 필요하다.

계산상 플레이 시간은 실제 전투 경과 시간에 결과·상점·재시작 20초/런, 레벨업 선택 2.5초/회, 성장 구매 1.5초/회를 더했다. 봇을 돌리는 데 걸린 PC 실행 시간을 플레이 시간으로 쓰지 않는다.

원본 저장과 분리한 프로젝트 사본에서 sandbox를 강제했다. 최종 사본의 Scripts, Resources, GameContent, Main 씬, Packages, ProjectSettings를 실제 프로젝트와 맞춘다. 배포용 Addressables 초기화 대신 동일 카탈로그의 에디터 에셋 참조를 해석하는 테스트 전용 부트스트랩을 썼다. 이 로더 변경은 실제 게임 소스에 적용하지 않는다. 사본의 일부 스크립트·패키지가 불완전했던 초기 측정은 최종 시간 근거에서 제외한다.

## 적용한 개선

1. 공통 성장 가격을 압축 이전 단계 비용의 합에서 현재 단계 곡선으로 분리했다. 저장 단계 변환 정보는 유지했다.
2. 생성량은 경험치 첫 노드 다음, 개체 수 상한·젠 수는 생성량 첫 노드 다음에 구매할 수 있게 했다. 직접 획득 반경은 유지하고 끌어오기만 성장시킨다.
3. 마나 성장 +8 MP/단계, 마나 드랍 확률 성장 +2.5%p/단계, 회복 2 MP/드랍으로 밀집 사냥을 뒷받침한다.
4. 재화 +15%/단계, 경험치 +16%/단계로 사냥량과 보상이 함께 성장하도록 조정했다.
5. 각 타입의 전체 위력과 두 보조 스킬 위력을 24단계로 확장했다. 타입마다 숙련 노드 21개를 추가했으며 한 노드당 구매는 세 번이다. 기존 구매 효과와 ID는 보존했다.
6. 숙련은 첫 세 단계 후 일정 비용으로 증가한다. 공통 성장부터 투자하는 기본 발사는 +1,000, 공통 성장을 물려받는 후속 타입은 +4,000씩 증가한다. 지수 가격의 마지막 몇 단계에만 대기 시간이 몰리지 않게 했다.
7. 결과창에 획득 경험치와 이전 동일 캐릭터·스테이지 런 대비 재화·처치·경험치 변화를 추가했다. 비교는 현재 실행 세션 기준이다. 텍스트는 입력을 받지 않는다.
8. 공통 완성 이후에도 타입별로 물량을 키우도록 무리 사냥 숙련 12단계를 추가했다. 해당 타입에서 생성 목표·최대 개체 수 +36, 젠 수 +6까지 늘어난다. 전용 지도에서만 구매하며 런 카드에는 나오지 않는다. 최종 필드 목표 202, 상한 260, 젠 수 21까지 성장한다.

## 재현과 검사

- 격리된 프로젝트의 `Assets/`에 CampaignPlaytest, `Assets/Editor/`에 CampaignLauncher를 복사한다. 실제 게임과 동일한 카탈로그 에셋이 로드되어야 한다.
- `-executeMethod ProjectDM.CampaignLauncher.Run -qaSuite projectile,flame,lightning,frost -qaMixed`로 기본 타입 새 저장 + 나머지 공통 완성 경로를 실행한다.
- `-qaSeeds 73,17`로 서로 다른 시드의 새 저장을 반복할 수 있다. `-qaSharedMax`, `-qaCharacter frost`로 후속 타입만 실행할 수 있다.
- `-qaEconomy`는 끌어오기 성장의 구매 우선순위를 높이는 비교 경로다. 위 수집 우선 샘플은 시드 17로 실행했다.
- 결과는 사본 프로젝트 루트의 `campaign-<타입>-<시드>-fresh/shared.json`에 저장된다.
- `Tests/ProgressionBudgetRegression.ps1`: 모든 실제 구매 가격, 네 타입 최대 강화 조합의 피해, 마나·몬스터 체력·개체 수·한 런 보상 범위를 검사한다.
- `Tests/GrowthTreeVisibilityAuthoredRegression.cs`: 모든 노드의 발견·구매 가능성, 숨김, 엑셀과 실제 에셋 일치를 검사한다.
- `simulate_current.py --prices-only`와 `Tests/CurrentBalanceParity.ps1`: Python과 C#의 현재 가격·드랍 계산만 비교한다. 과거 공용 스킬을 쓰는 Python 전체 전투 모델은 현재 타입별 시간 근거로 사용하지 않는다.

최종 검사 결과:

- Unity 실제 Main 씬과 수정하지 않은 운영 Addressables 로더: `PRODUCTION_BOOTSTRAP_PASS`.
- 실제 작성된 성장지도·엑셀 동기화·전체 구매·한 단계 앞 숨김·겹치는 노드 중심점·타입별 물량 및 다음 런 스냅샷·런 카드 제외: 3,809개 검사 통과. 공통 92노드/266구매, 발사·화염·번개 각 41노드/117구매, 빙결 44노드/125구매이며 해금이 막힌 노드가 없다.
- 전체 구매 가격과 최대 강화의 피해·마나·몬스터 체력·생성량·한 런 보상: 785개 검사 통과. 100만 미만 기준을 만족한다.
- 가격·드랍 계산 Python/C# 대조: 1,024개 검사 통과. 현재 가격 298개와 등급 보상 사례를 비교했으며 아카이브 전투 캠페인은 실행하지 않았다.
- 진행 규칙·저장 이전·구성·결과 집계·수치 표시·등급·드랍·목표 라인의 관련 PowerShell 회귀 검사 통과.

캠페인에서는 동일 카탈로그의 에디터 참조로 에셋을 로드했다. 이후 테스트용 로더를 제거하고 실제 Main 씬을 운영 Addressables 경로로 부팅하는 검사도 별도로 통과했다. 실제 게임의 AssetLoader 코드는 변경하지 않았다.

## 한계

공통 성장을 이미 보유했거나 재화를 미리 모아 두면 후속 캐릭터 성장이 빨라진다. 정확히 세 시간을 강제하는 시간 제한·재화 소멸·캐릭터별 별도 재화는 추가하지 않았다. 보스는 180초 도달 미리보기이며 실제 보스 전투는 구현되어 있지 않다. 따라서 보스 공략과 최종 스테이지 완성까지의 완제품 분량을 측정한 결과가 아니다. FPS나 프레임 시간 측정도 이 가속 전투 봇 결과에 포함하지 않는다.
